## 1. 目的・旧設計との関係

◎は「今回の相手と条件で最も勝つ可能性が高い馬」という**市場非依存の順位**。
★は「その推定と実際に観測できた市場価格との差」という**別評価**。
◎だから買う、★が高いから勝ちやすい、という同一視をしない。
プロジェクト全体の最終目的はEVの改善であり、◎の精度だけで目的達成とは言わない。

2026-09の「市場を原則採用してゲートで上書き」とは◎の入力設計が異なる。
今回のユーザー指示に従い独立能力評価を新しい設計案とするが、旧案・失敗の記録は消さない。
旧ゲートや現行VHの市場混合確率を入力として引き継がない。本番の差し替え承認でもない。

想定する評価の考え方は「条件を考慮した過去の競走内容→今回条件との一致→今回相手との比較」。
独自性・性能を実証した理論ではなく、今後検証すべき仮説である。

## 2. 一方向の処理と情報の境界

```
日付制限済みraw → 独立入力 → 能力・適性の加算評価 → 勝率近似p → ◎
                                                        │
時刻付き市場価格（別入力）───────────────────────────────┴→ ★
凍結した予測・購入計画 → 正解/払戻との結合 → 評価（承認後のみ）
```

◎層では、現在だけでなく**過去のオッズ・人気も禁止**。
現行VH確率・EV・Edge・星・市場依存スコア、市場順位で選んだ学習サンプルも禁止。
horseId/raceIdは結合・追跡専用、馬名・レース名の自由文は学習に入れない。
騎手/調教師IDの高次元暗記や、人気の代理となる外部評価の接続も初版は行わない。
市場は◎を選び直せず、価格が変化しても◎と独立pが変わらない構造をテストする。

既存prepareInputには過去oddsRaw/popularityが含まれ、runnerはhistoryの列を厳密に検査しない。
将来はその後ろに独立層専用のホワイトリストを設け、未知列も拒否する。
現在の基盤をそのまま渡して「オッズは使わない約束」に頼らない。

## 4. 除外する入力とリーク対策

- 最終オッズ・人気順位・払戻は◎入力から完全除外。現在結果の着順・上がり・着差・通過・タイムも禁止。
- **現在馬場・天候・馬体重**は保存欠損0でも発走前観測の証拠がないため初版から除外。
  過去馬場実績を「今回馬場適性」に変換するために現在の事後馬場を接続しない。
- 血統・調教・ラップ/区間タイム・不利情報・確実なコース形状は今回の確定入力にない。
  上がりと通過だけで展開、不利、消耗度の正解値を捏造しない。
- 過去着差rawは今回の対象履歴では数値形式だが、結果ページのハナ/クビ等と単位が同じとみなさない。
  意味確認前に馬身→秒係数を決めたり、空欄の勝ち馬を0で補完しない。
- 現在の騎手/調教師成績、全期間の平均タイム・標準化・欠損補完値・クラス別平均は禁止。
  7,851頭限定の履歴集合で作った騎手勝率は母集団が偏るため初版では作らない。
- 個体の過去相手を評価する際は `opponentHistory.date < historicalRace.date < target.date`。
  相手の後の出世を遡って「当時の強敵」にする処理は禁止。
- 同一日の結果による更新なし。学習例自身の特徴量もその日以前で作る。
  モデル重み・校正・標準化・欠損処理の学習終了日も対象日より前に固定。
- 過去走がない馬に旧仕様の65点を与えない。学習区画だけの縮約された事前値と
  「根拠不足」を別管理する。これは平均能力の証明ではない。
- rawは不変。派生層はsource hash、元race/horse ID、使用履歴日付、単位、変換版、
  欠損理由、学習終了日を持つ。データ欠損/構造上不要/形式不明/時刻証拠なしを区別。

## 5. モデル構造の提案

初版は自由度を抑えた**正則化付き加算モデル＋レース内確率化**を一つだけ設計対象とする。
大規模木モデル・多数の埋め込み・ROI最適化を初手にしない。

各馬の独立評価:
`s_i = A_i（過去内容）+C_i（今回条件への適合）+W_i（斤量等）+U_i（欠損/縮約）`。
各ブロックは少数の明示的な変換の加算。重みは訓練区画の結果だけで学習し、
都合のよいROIを生む手作業の点数配分はしない。今回重みは決定・推定していない。

`p_i = exp(s_i/T)/Σ全出走馬 exp(s/T)`、T>0は訓練内の時系列予測で校正する。
◎はargmax p（同率は馬番、同率であることも表示）。市場混合をしない。
同一レースの距離やクラスを単に全馬へ同じ加点しても順位は変わらないため、
馬の過去内容との差・相互作用として使う。相手関係はこの**全頭**の比較に反映する。
上位8頭だけの再正規化を繰り返さない。

第一学習目的は勝者の対数損失＋正則化。真の勝率が得られたとの主張は校正検査前にしない。
同着の専用尤度を未実装の初版では、事前規約として同着レースを学習・確率校正から除き、
予測保存・的中評価・確定払戻精算には残し、除外数を明記する。結果を見て規約を変えない。
中止は勝ちラベル0だが、過去能力の最下位点には変換しない。取消は出走集合制約として別記。

馬券内の確率は勝率と別の定義が必要。初版は◎の実際の3着内/複勝対象率を評価できる構造まで。
将来の順位確率を作るなら全頭の順序分布＋同着/少頭数対応を別途検証し、
単勝pから無検証で複勝・ワイドpを確定しない。

### 数値による説明

各馬・各レースに以下を保存する設計:

- 元値・単位・過去raceId・使用件数・最新履歴日・欠損理由。
- 変換値と学習区画、各ブロックの加算値、合計s、校正前後p、順位。
- ◎と2位の差について `Δs=ΔA+ΔC+ΔW+ΔU` を厳密に再合計できる内訳。
- レース内の相手分布、未知履歴の馬数、競合馬との評価差。
- 点数と勝率の非線形変換を分ける。「斤量が勝率を何pt改善した」等の因果説明はしない。

## 6. ★の設計（◎とは別）

◎の固定済みpと、別経路のMarketSnapshotを受け取る。
snapshotにはraceId/horseId、取得時刻、発走予定時刻、観測オッズ、取得元、鮮度を必須とする。
時刻証拠なし・締切後・未校正pなら **★=未評価**。0星や低評価に置き換えない。
現developmentには事前価格がないので、通常経路の★は全件未評価になる設計。

価格が利用可能なら `q_i=(1/o_i)/Σ(1/o)`、`Edge=p_i−q_i`、`EV=p_i o_i−1`。
★は◎以外の馬にも付き得る。pの不確かさと価格の鮮度を併記し、
既存の「EVを5段階へ直結」を流用しない。初版は連続値と評価可否だけにとどめ、
0〜5の境界や購入閾値は未決定。別途承認・事前登録後に決める。

途中オッズは確定払戻率を保証しないので、表示は観測価格に対する暫定EV。
最終オッズによる★は、将来承認された場合だけ評価側の「事後参考」として別保存し、
◎・校正・学習・本番推奨へ戻さない。オッズ時系列取得の実装は今回も行わない。

## 9. 比較方法と評価項目（今は実行しない）

同じ外側検証raceId・同じ実出走集合・同じ評価可否で比較する。

## 10. 最初に実装する範囲の提案

**別途承認後**、まず以下だけを小さく実装するのが妥当。

1. 独立入力の契約・二段の日付ガード・市場列除去・raw派生の来歴と欠損理由。
2. 合成データで説明の再合計、オッズ/人気を全変更しても◎入力・結果が不変、
   同日/未来の履歴と正解を書き換えても予測不変、予測順・seed再現性を検査する。
   市場・結果への別ファイルアクセスもコードレビューし、同一プロセス凍結だけを防壁としない。
3. 初期特徴量は過去の順位/頭数・履歴件数・休養・距離/表面差・過去通過位置・斤量差と
   性齢等の静的情報に限定。組合せ後の有効件数を再監査する。
   着差単位、基準タイム、過去クラスの確認を通るまでは条件付き項目を入れない。
4. 加算モデルを1本だけ接続する段階はその後。重み・校正を訓練だけで求め、
   来歴付き数値説明と基本◎を保存する。★は未評価のまま。
5. 頑健性検査・時系列性能検証は前述の規約を凍結してから別途実行承認を得る。

初版の主対象案は平地1,321R。障害17Rは競走構造が異なるため、価格も結果も見ずに
「未対応」として母集団とcoverageに残す。性能が悪いから除いたわけではない。
新馬/過去走なしの馬は除外せず、履歴不足と訓練内事前値を明示する。
障害や全入力不正のRで架空の等確率を作って「全件予測済み」にしない。

区画ごとの凍結モデルを呼び分け、未対応Rを記録する薄い実行層が将来必要。
