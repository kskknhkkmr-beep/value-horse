# development 時系列シミュレーター基盤

2026-10-09作成。今回の範囲は基盤・合成テスト・入力の構造確認のみ。
現行VH、新モデル、買い方の性能検証や最適化は実行していない。

## 入力と正解の分離

通常入口は `scripts/simulator/input.ts` の `loadDevelopment()`。
次の3ファイル以外は、ファイルを開く前に拒否する。

- `lib/backfill/races.json`: developmentのレース・実出走馬集合。
- `lib/backfill-stage1/race-details-raw.json`: 静的な出走情報と別区画の確定結果・払戻。
- `lib/backfill-stage1/horse-history-raw.json`: raw過去走。

1,338レース、7,851馬、2026-02-07〜2026-06-21の集合・ID・日付・馬番を検査する。
リンク経由で別データへ移動する入力も拒否する。固定評価と完全版原本は入力にしない。
元ファイルを変更する処理はない。正解は深く凍結したコピーで保持し、SHA-256を記録。
これは論理的な読み取り専用と改変検出であり、OS上のアクセス権変更ではない。

`prepareInput()` が明示的に許可した項目だけを予測用へコピーする。
出走馬ID・馬番・枠番、性齢、斤量、騎手、調教師、距離・芝ダ・競馬場・クラスと、
**history.date < targetRace.date** の過去走だけを渡す。同日の別レースも除外し、
対象race ID自身も日付にかかわらず除く。raw表現は保持し、新特徴量は生成しない。

現在レースの着順・タイム・着差・通過順位・上がり・確定オッズ・人気・払戻は渡さない。
公表時刻を確認できない現在馬場・天候・馬体重も渡さない。
結果は、全レースの予測と買い方を確定した後で初めて記録に結合する。
同日内の先行レース結果による学習・モデル更新も今回の基盤では行わない。

## 実行と版の保存

`runner.ts` はモデルと買い方のコールバックを受け取るだけで、VHアダプターや
新モデル・推奨購入ルールを内蔵しない。実データ用の予測・評価CLIも提供していない。

将来、別途承認されたモデルを接続するAPI順序は以下。

1. `loadDevelopment()` でdevelopment全件を読み、構造を検査。
2. `simulate(dataset, model, policy, seed, simulatorFingerprint())` で予測を固定。
3. `saveRun(run)` でモデル・買い方の版別に保存。
4. **評価を承認された時だけ** `settleRun(run)` と `metrics(events)` を呼ぶ。

モデルと買い方には名前・版・コードのSHA-256・設定・学習終了日を必須記録。
学習終了日はすべての対象日より前でなければ拒否する。nullは未学習の固定処理という
明示的な申告。パラメータの実際の学習履歴や外部モデルコードのハッシュは接続者の
責任で確認する。学習済み重みを日付フィルターだけで安全とみなしてはいけない。
今回、学習器や日ごとの再学習処理は実装していない。

同じデータ・モデル・買い方・seed・基盤コードなら同じrun ID／JSONになる。
キーの順序を固定してハッシュ化し、同率予測は馬番で決定的に順位を付ける。
seed付き乱数を渡し、モデルと買い方を同じ入力で2回呼んで不一致を拒否する。
モデルは全出走馬について有限の0〜1の勝率（合計1）と理由のraw値・寄与・説明を返す。
不正な確率を勝手に補正しない。実出走馬・予測順位・勝率・理由・馬券・実着順と
全券種の確定払戻を各レースの記録に保持する。

コールバックは凍結した事前入力のみ受け取る。ただし同一Nodeプロセスなので、
外部ファイル読込・グローバル変数・時計・Math.random等を完全に封じるセキュリティ
サンドボックスではない。接続モデルは純粋・決定的な処理で、結果ファイルや
現在の騎手成績・scores-cacheを別途読まないこと。2回一致だけでこれを証明はできない。

保存先はGit管理外の `lib/simulation-runs/<runId>/` のみ。
`run.json` と `manifest.json` を排他的に新規作成し、既存版を上書きしない。
中断して不完全な保存先が残った場合も自動上書きせず停止する。
入力・正解・取得元3ファイル・基盤コード・設定・seedのハッシュを保存し、再読込時に
整合性を検査する。保存時刻は再現性のあるrun IDに混ぜない。
`compareRuns()` は同じ事前入力／正解スナップショット同士だけを比較し、
予測・馬券の変更をrace IDごとに返す。成績比較を自動では行わない。

## 市場比較と7券種の会計

`marketTopN()` は正解側の確定人気順位（既定）または確定単勝オッズから
市場1位・上位N頭を返す。欠損なら停止。予測・買い方には渡さない。
これは**事後の市場参照値**であり、発走前オッズを使った実行可能な買い方の再現ではない。
同値は馬番で決める。比較基準を選んだ設定も将来の評価記録へ残すこと。

単勝・複勝・ワイド・馬連・馬単・三連複・三連単は100円単位のTicketで表現。
ワイド・馬連・三連複は順不同、馬単・三連単は順序を保存し、同着等の複数払戻も照合。
raw組合せ／払戻の件数と解析entriesが食い違う場合も未解決にする。
返還・発売なし・欠損・パース異常を外れやゼロ円にせず、未解決が残れば集計を拒否。
返還は将来、券種・組合せごとの確認済み証拠を `Truth.refunds` に追加した場合だけ処理。
現在の取得データにはこの構造化された返還証拠がない。無条件に全額返還しない。

`metrics()` が用意する会計と定義：

- 購入総額・返還額・リスクにさらした購入額（購入総額−返還）・受取総額・円損益。
- net ROI = 円損益 / リスクにさらした購入額。分母0はnull、返還分は分母から除く。
- レース的中率（購入レースのうち1枚以上的中）、馬券的中率を別々に記録。
- 最大DDは初期残高0からの利益累計の最高点との差。正の円額で記録。
- 最大連敗は「購入したが1枚も的中しなかったレース」の連続数。
  非購入・全返還レースは連敗を伸ばしもリセットもしない。赤字レース数とは異なる。
- 的中間隔は全レース間隔・購入レース間隔・暦日間隔をそれぞれ記録。

会計は日付→結果ページの発走時刻欄→race IDの順で、同一レースの馬券を一括決済。
実際の発走遅延や同時刻レースの厳密な順序は不明で、DD・連敗・間隔はこの順序に依存。
時刻欠損件数とこの制約を集計結果に残す。

これらの集計は所見を候補化するための十分条件ではない。将来の検証では既存の
的中20件・レース単位bootstrap CI・上位1〜2的中除外・独立した的中集合確認・
円損益とDD併記・事前の構造仮説という全ルールを守る。今回CIや候補選別器は実装しない。

## 実データ上の制約

- 最終単勝オッズしかなく取得時刻の証拠がない。現行VHの市場ブレンドを
  真の発走前条件で再現するには時刻付きのオッズが必要で、今回代用品は入れない。
- 馬場等は結果ページ時点なので、発走前に観測済みと断定しない。
- 出走集合は実出走馬18,870頭。結果ページに追加される取消・除外71頭は正解側に
  保持するが、事前発表された全頭・取消発表時刻は復元できていない。
- 性齢・斤量・騎手・調教師等も結果ページからの静的再構成。事前キャプチャではなく、
  直前変更や事後訂正を完全には証明できない。厳密な時点証明には別の保存データが必要。
- 過去走の欠損・地方／海外の正規化不能・短縮raceIdの年衝突はraw基盤の仕様通り。
  主キーには12桁netKeibaRaceIdを使い、未知・欠損を補完しない。
- 血統・騎手集計・スコアの時点別スナップショットは今回ロードせず、VH接続も未実装。
