# VALUE HORSE 判断の履歴

**このファイルの目的は「同じ過ちを繰り返させないこと」。**
新しい開発AIが「なぜこうなっているのか」を理解せずに巻き戻すのを防ぐため、
確定した判断と、その理由を時系列で残す。

---

## 0. 大前提：このプロジェクトの目的

**市場（オッズ）が付けた確率と真の確率の乖離を検出し、期待値（EV）を最大化する。**

的中率の最大化ではない。AUCの最大化でもない。
「よく当たる予想」は市場のオッズをそのまま読めば手に入る（それが市場1位）。
VALUE HORSEが価値を持つのは、**市場が間違えている場面を特定できたときだけ**。

だから評価軸は常に「市場と比べてどうか」であり、モデル単独の精度ではない。

## 2. 撤回した4つの仮説 — **最重要**

すべて「母集団が負けている中から、都合の良い部分集合を探す」形で見つかり、
標本を増やすか頑健性を確認した時点で消えた。**この4件は同じ病気の4つの症例である。**

### ① EDGE_MIN=0.05 × ODDS_MAX=20（閾値の絞り込み）
ROIがプラスに見えたが**単勝的中6件**。標本不足でノイズと判定し撤回。
→ [`threshold-sweep-decision.md`](threshold-sweep-decision.md)

### ② 芝×~1800m の複勝ROIがプラス圏かもしれない
- 半年前（43件）: −6.8% [−34.2, **+23.5**] ← CI上限がプラスに触れていた
- 6ヶ月データ（197件）: **−21.9% [−32.8, −10.7]** ← マイナス確定

**学び: 標本不足による広いCIが「かもしれない」を生んでいただけ。**

### ③ 新馬セグメントでモデルAUCが市場に優位
- 半年前（複勝的中14件）: AUC差 +0.026 〜 +0.042
- 6ヶ月データ（85R）: AUC差 **−0.007 〜 −0.001** ← 消失

**学び: 母数の小さいセグメントの優位は、まずノイズを疑う。**

### ④ 芝×マイル(1401〜1800m) 単勝 ROI +11.0%（2026-09-02 に発見・即日撤回）
的中33件と「20件以上」を満たし、v2/v3両方でプラスだったため一度は候補化した。
だが2つの頑健性チェックで崩れた。

**(1) 高配当への依存**

| 除外件数 | v3 ROI | v2 ROI |
|---|---|---|
| 除外無し | +11.0% | +17.1% |
| 上位1件除外 | +3.9% | +9.8% |
| **上位2件除外** | **−3.2%** | +2.5% |
| 上位3件除外 | −9.8% | −4.3% |

オッズ43.5倍・43.4倍のわずか2件を除くだけで符号が反転。
599点の母集団のROIを、少数の的中が支配していた。

**(2) v2/v3は独立な確認ではなかった**

| | v3 | v2 | 共通 | Jaccard |
|---|---|---|---|---|
| 選定馬 | 599点 | 583点 | 519点 | 78.3% |
| **的中** | 33件 | 34件 | **31件** | **86.1%** |

「2つのバージョンで同じ結果が出た」は、**ほぼ同一の的中集合を2回数え直しただけ**。
v2とv3はjockeyScoreの算出法しか違わず、選定基準への影響が小さいため当然だった。

**→ この④が、統計ルール（§3）が現在の形になった直接の原因。**

## 3. 統計ルール（決定済み・緩和禁止）

新しい所見を「候補」と呼ぶ前に、**全項目**を満たすこと。
各ルールには、上の §2 に実際の失敗例が対応している。

| ルール | なぜ（対応する失敗） |
|---|---|
| **的中20件未満は候補から除外する** | ①（的中6件でROIプラスに見えた） |
| **レース単位ブートストラップCIを必須とする** | ②（CI幅が標本で半減し、上限がマイナスへ落ちた） |
| **上位1〜2件の高配当的中を除いてもROIの符号が変わらないか確認する** | ④(1)（上位2件で符号反転） |
| **v2/v3等で一致しても、同じ的中集合を数え直しただけではないか確認する** | ④(2)（的中Jaccard 86.1%） |
| **ROIだけでなく円換算損益と最大ドローダウンを併記する** | ROIは母数を隠す。−27.4%は「半年で−485万円」である |
| **仮説はデータを見てから探すのではなく、構造的理由を先に立ててから検証する** | ①〜④すべて（後付け探索だった） |

**「20件以上・v2v3一致」だけでは不十分だった**というのが④の教訓。
そこから (3)(4) の2ルールが追加された。

## 4. なぜ「探索」をやめて「二段階アーキテクチャ」へ向かうのか

514件のdisagreementから「良さそうな部分集合」を閾値やセグメントで探すのは、
§2 の4件とまったく同じ操作である。母集団が −31.0% のとき、
部分集合を切ればプラスに見えるものは必ず出るが、それは再現しない。

そこで**問題設定そのものを組み替える**：

- 現行 = 「全馬の真の勝率を推定し、argmaxを1位とする」単一の確率推定モデル
- 転換後 = **Stage 0: 市場を受け入れる（71%はそのまま）**
        **Stage 1: 「市場を上書きすべきか」だけを判定する独立したゲートモデル**

これは selective prediction / learning-to-defer の枠組みに乗るので、
評価方法論（risk-coverage曲線、事前登録された成功基準）も借用できる。

**「市場を上回る予想を作る」から「市場の監査役になる」への転換。**

ただし [`gate-model-design.md`](gate-model-design.md) §5 の通り、
これは小標本問題を解決しない。**厳しいゲートほど検証標本が枯渇する**というジレンマは残る。
加えて Phase 3 で同じ514件を探索的に見てしまっているため、
そのまま学習・評価に使うと二重利用になる。
→ **だから先にホールドアウトを凍結する**（[`NEXT_SESSION.md`](NEXT_SESSION.md)）。
