# Stage 1：競走種別の読み込み補正

2026-10-10。development 1,338Rだけを構造確認した。性能計算・実データの再学習・新予測は実施していない。
[弱点調査](STAGE1_WEAKNESS_RESEARCH.md) をmainに競合なく統合した後の修正。

## 原因と根拠

developmentの29Rは保存surface=芝だが、レース名と取得済みクラス表記が障害を明示する。
取得経路は backfill-fetch.ts → fetchDbRacePage → parseDbRacePage。
本番 lib/scraper.ts の旧距離正規表現は競走種別候補と距離の間を最大4文字に制限している。
developmentの202606030404（2026-04-05）の公開結果ページを1ページだけ確認すると、
コース表記は「障芝 ダート2880m」、条件表記は「障害4歳以上未勝利」だった。
「障」以降の「芝 ダート」は5文字なので一致せず、次の「芝」から一致して芝と判定する。
同じ表記で旧正規表現の誤判定と新分類を回帰テストに固定した。
当時のHTML保存はないため、29ページすべての取得当時HTMLを再確認したという意味ではない。

本番パーサーは今回変更していない。将来の取得でも同じ問題が起き得るが、
developmentローダーの補正で平地モデルへの混入を防ぐ。

## 補正・除外

scripts/simulator/race-kind.ts の development-race-kind-v1 を使用。
障害/ジャンプの名前・クラス、J・GI等の障害グレード、保存済み障害種別、
障で始まるコース表記を根拠とし、物理的な芝/ダートより競走種別を優先する。
根拠の矛盾・判別不能はunknownとして平地入力から除外する。距離や成績による判定はしない。

- 元JSONは変更しない。読み込み後のRaceSpecに補正し、元surface・根拠・除外理由を別記する。
- 独立◎の学習候補・予測候補は芝/ダートのみ。障害/unknownは除外ログを残す。
- 平地入力の過去走からも障害/unknownを除外。対象日より前、対象raceId以外という既存ルールを維持する。
- 直接モデルを呼ぶ場合も非平地・障害過去走を拒否する。
- 入力/学習成果物に分類版を記録。旧分類の保存モデルは拒否し、別途承認なしには再学習しない。
- 実行結果に分類表、学習除外理由、予測不可理由を保存する構造。実行指紋に分類コードを含める。
- 旧弱点集計スクリプトは補正入力と旧保存予測の混在を拒否する。旧版での再現には履歴commitを使用する。

## 既存監査の扱い・制約

初回診断・弱点調査の保存766Rには今回の29Rのうち24Rが含まれる。
数字は旧分類の保存集合の記録として保持し、補正後平地モデルの性能とは呼ばない。
旧モデルの重みを補正入力に流用しない。補正後の再学習・再診断は別途承認を要する。
成績改善を示した修正ではなく、対象定義の修正である。

履歴のクラス/グレードは十分に保存されておらず、履歴は名前と種別で判断する。
保存名にも種別にも障害の根拠がない誤記まで保証するものではない。
事前時刻付きオッズ・当時の馬場/馬体重の取得時刻など、従来の制約は残る。
本番の表示・取得、Stage 0計算、取得済みJSON、固定評価は変更/参照していない。
