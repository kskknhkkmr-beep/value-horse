## 2. 4方式と名称

今回のA〜Dは「買い方」の識別子。アブレーションのモデルA〜D、
前回着順監査のA/B/Cとは異なる。全方式のVH順位は同じ保存v2を使う。

|方式|軸|相手の並び|
|---|---|---|
|A|VH v2のrank 1|VH v2保存順位|
|B|VH v2のrank 1|最終市場人気順位|
|C|最終市場1番人気|VH v2保存順位|
|D|最終市場1番人気|最終市場人気順位|

- VHの◎は保存rank 1をそのまま採用。再推論、条件付き乗換え、v1への代替はしない。
- 全方式で「自分の軸」をhorseIdで相手リストから除いてから、必要頭数を上から選ぶ。
  市場軸の場合、VHのrank 1が別の馬なら相手に含まれてよい。別方式の軸は除かない。
- 市場順位は保存された確定単勝人気（final-popularity）昇順、同人気は馬番昇順。
  確定単勝オッズは正の数値であることを構造検査するが、人気欠損をオッズで補う切替はしない。
  全startersの有効な人気を要求し、1番人気が存在することを確認する。欠損時に2番人気を軸にしない。
- VH順位は保存rank昇順。確率同値は既存保存規約の馬番昇順。
  rank重複・欠番・馬の対応不整合は同点扱いにせず停止する。
- 最終市場情報は事後比較用の隔離した入力。学習やVH順位に混ぜない。
  B/C/Dは購入時点で実行できた戦略とは呼ばない。

## 3. 固定買い目・予算

初期案をこの版の固定規約として採用する。券種ごとに全4方式の点数・投資を揃える。

|券種|相手頭数|組合せ|点数|1点|1方式・1Rの投資|
|---|---:|---|---:|---:|---:|
|ワイド|上位3頭|軸と相手各1頭|3|1,000円|3,000円|
|三連複（sanfuku）|上位4頭|軸と相手4頭から異なる2頭の全組合せ|6|1,000円|6,000円|

- 相手候補を重複なしで確定し、三連複の相手ペアは4頭から2頭、6組を漏れなく採る。
- 各券は馬番を数値昇順へ正規化。キーはraceId / 券種 / ソート済み馬番列。
- 軸を含む2頭/3頭は必ず別horseId。重複券を金額合算して点数を偽装しない。
- 各方式内の重複はエラー。他方式と同じ券になることは許容し、重複を診断に残す。
- ワイドと三連複は別会計・別比較。3,000円と6,000円の損益額を予算同等の成績と比較しない。
  合算ポートフォリオや金額配分の探索はこの版の対象外。

## 4. 共通集合・欠損・取消

基礎集合はdevelopment 2026-02-07〜06-21の平地に対する保存v2/市場共通742R
（保存予測日2026-04-04〜06-21）。旧Stage 0の推奨なし63Rで絞った679Rは使わない。
初期平地527R、予測不可23R、障害46Rは既存除外のまま。種別不明も対象外。

**主比較は4方式×2券種すべてに共通の一つの集合Sを使用する。**

1. まず、実出走として保存された同じstartersを全方式に使う。VHと市場の全馬順位が存在すること。
2. 両券種共通のため5頭以上を要求する。4頭ならワイドだけは作れても、この主比較では全方式・両券種から除く。
3. 結果を見ない生成フェーズで4方式の軸・相手・予定券をすべて確定し、ハッシュ保存する。
4. 正解照合フェーズで一方式・一券でも未解決、返還、発売なし、取消/除外等の問題があれば
   そのレースをSから全方式・両券種共通で外す。予定券を別馬で作り直さない。
5. SのraceId、券数、投資額が全方式で完全一致してから会計・比較する。

構造不整合（IDの取り違え、ハッシュ不一致、重複raceId、保存rank異常）は単なる除外で隠さず、
処理全体を停止して報告する。正規のデータ欠損は「評価不能」と理由付きで記録し、
欠損/返還のレース・券数を方式別と共通除外別に報告する。払戻を推定しない。

- 取消/除外馬は結果側にあっても、元から保存starters外なら候補に追加しない。
- 生成後に選定馬の取消/除外が見つかった場合、繰上げ候補・予算振替は行わない。
- 中止・失格・降着は取消と同一扱いにしない。確定払戻が完全なら予定券をそのまま精算する。
- 券別返還が確認できれば精算ログには返還として保存するが、主比較からは共通除外。
  一方式だけ返還される場合の実質投資の不一致を、この版では許容しない。
- 全返還・レース取消は成績上の外れにしない。欠損も非購入と混同せず評価不能と明記。
- 今回Sの最終件数は未算出。742Rすべてを評価できるとは断定しない。
- 保存出走集合は実出走馬に基づく事後再構成。取消発表前の全頭や購入時刻は再現できない。
  Sは「完全に精算できる事後共通集合」であり、実運用の全レースを代表しない。

## 5. ID・保存順位・払戻の監査契約

実装時には、買い目生成に先行する構造監査と、生成後の精算監査を分離する。

### 保存と識別

- レース主キーは12桁netKeibaRaceId、馬主キーは安定した文字列horseId。
  レース内対応はraceId / horseId / horseNumberの3点で検証する。
- 保存starters・predictions・development原データ・truth.horses間で馬IDと馬番を突合。
  同一レース内で双方が一対一で、全startersに全順位があることを確認する。
- 馬名、配列順、短縮raceId、engineの位置依存数値IDをjoinキーに使わない。
  別レースで同じhorseIdが出ることは正常で、レース内重複とは区別する。
- 本番scores-cacheや旧Stage 0スコアを入力にしない。今回必要なのは保存v2の順位。
- 保存rankが1..出走数、確率が有限で0〜1かつ合計1、確率降順・同値馬番順と整合すること。
  rank/確率不整合を再ソートで自動修復しない。理由と寄与は既存のまま保持する。
- 独立scoreフィールドは保存されていない。理由のcontribution合計が説明用logitスコア。
  この値を新たな相手選択基準にしたり重みを再計算したりしない。
- 保存run/manifestの内容ハッシュ、入力/正解ハッシュ、既存監査の保護hashを照合。
  3学習窓と各予測日を検査し、未来の係数を過去の予測へ戻さない。
  正解側にだけいる取消/除外馬は別ログとして許容するが、全startersのID/馬番対応は必須。

### 払戻・特殊ケース

- 既存settleTicketの順不同照合を再利用。wideは2馬番、sanfukuは3馬番の集合一致。
  的中は確定entriesで判定し、単なる「双方/全馬3着以内」で代用しない。
- 100円当たり確定払戻×（1,000/100）で券を精算。複数的中なら全券の払戻を合計する。
- 同着の複数組合せ・複数行をすべて保持。最初の1行だけを採用しない。
  同じ正規化組合せの重複・矛盾は勝手に合算せず未解決として報告する。
- raw組合せ数とraw払戻数とentries数、券種の馬数、正の整数払戻、馬番範囲・対応を検査。
  完全なstatus=okの表に予定券がなければ外れ。欠損表にない券は外れではない。
- 返還はTruth.refundsの券種・馬番集合・証拠が一致する場合のみ。現rawに券別返還証拠がないケースを
  「取消だから全額返還」と推定しない。unparsed/refund/not_offered/missingは未解決扱い。
- 全方式の全予定券について、正規化キー、対応horseId、照合先entries、精算状態と理由を記録する。
- 生raw、保存run.actual、解析entriesを少数の固定サンプル（期間ごとの日付/raceId先頭、
  存在すれば特殊ケースの同じ先頭基準）で手動照合する。高配当/成功例を選別基準にしない。

## 6. 評価指標・共通会計

券種ごと、S上の各方式について以下を出す。結果が悪くても省略しない。

- 購入レース数・券数・的中レース数・的中券数。
- 主的中率＝1券以上的中したレース数/Sのレース数。券的中率も別掲する。
  レース黒字率や軸3着以内率とは区別する。
- 総投資、返還、払戻、円損益。ROI＝円損益/（総投資−返還）。
  主比較は返還なしなので分母はワイド3,000×|S|、三連複6,000×|S|で全方式同額。
- 初期残高0からレース別損益を累積し、最大DDは累積最高点からの最大下落額を正の円額で示す。
- 最長不的中連続数は「購入して的中券が0のレース」の連続数。
  的中してもレース収支赤字の場合は不的中と数えない。
- 時系列順は日付→保存発走予定時刻→raceId。予定時刻欠損は末尾（99:99）に置き件数を記録。
  実発走遅延は不明。非対象レースは不的中連続数を延長もリセットもしない。

### CI・比較・頑健性

- レース単位の対応付きbootstrap 10,000回、seed=20261011、percentile95%CI。
  一つの再標本化raceId列を4方式・両券種に共通適用し、同一レースの全券をまとめて抽出する。
- 各方式のレース的中率・ROIと、全6方式間差（A−B、A−C、A−D、B−C、B−D、C−D）のCIを出す。
  各反復で損益/投資を再集計し、券を独立標本として水増ししない。
- 主対比は各券種のA−D。他の対比と寄与分解は診断用。
  未補正95%CIを多数比較した結果から勝者を正式採用しない。日/開催内の依存も十分に表現しない。
- 高配当感度は券種別に、全4方式でそのレースの「的中券単体の最大払戻」を指標にする。
  降順、同額は日付→raceId→正規化券キー順。異なる上位1/2レースを選び、
  4方式から共通で当該レースの全券・全投資を除く。的中がなければ該当なしと記録。
  券種間感度の直接比較はせず、各券種内で同一残存集合を用いる。符号・損益・DDを再掲する。
- 期間別は固定4月/5月/6月。Sを月で区切り全方式を同一集合比較。
  期間別のDD/連続不的中は各月先頭で初期化と明記し、全期間とは別表にする。
- 軸一致/不一致別もSを固定して全方式を比較。好成績の群を運用条件にしない。
- 的中20件未満は参考値のみ。複数券が同一レースで当たっても、候補判定では
  独立性を過大評価しないよう最低20的中レースを要求する。
- 同一的中券のJaccardをraceId / 券種 / ソート馬番で記録し、的中レース集合の重複も併記。
  同じ券や同じ的中を4方式で数えて独立検証と扱わない。

## 7. 軸と相手の寄与の切り分け

2×2比較の各差を、S内の各レース的中指標と券種別レースROIについて計算し、同じbootstrapでCIを出す。

- 軸固定で相手を替える：A−B（VH軸）、C−D（市場軸）。
- 相手順位規則固定で軸を替える：A−C（VH相手）、B−D（市場相手）。
- 平均の軸差：((A−C)+(B−D))/2。
- 平均の相手規則差：((A−B)+(C−D))/2。
- 交互作用：A−B−C+D。相手規則の差が軸によって変わるかを記述する。

軸変更により「除外される相手」も変わる。したがって軸差は純粋な能力の因果効果ではなく、
この固定買い目規則全体での置換差である。相手規則差も学習特徴量の因果効果ではない。
軸が同じならA=C、B=Dの券が一致すること、相手集合も同じなら全券が一致することを検査する。
軸単体3着以内、相手内の確定払戻対象馬の包含、的中券の一致/不一致を説明ログへ残すが、
これを使って追加ルール・相手頭数を作らない。
